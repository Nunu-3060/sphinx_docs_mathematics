9. Python による実装

本章では、CA を Python で実装するときの基本的な方法と注意点をまとめる。本書のサンプルコードはすべてこの章の方針で書かれている。各サンプルの一覧と実行方法は、付録の「サンプルコード一覧」を参照してほしい。

9.1. 基本方針

CA の実装で最も重要なのは、次の 2 点である。

  • 同期更新を正しく実装する：次の時刻の配置は、必ず現在の配置だけから計算する。現在の配置を表す配列を書き換えながら計算してはいけない（第 2 章「基本概念と定義」を参照）。

  • セルごとのループを避ける：Python の for 文でセルを 1 つずつ処理すると非常に遅い。NumPy の配列演算を使って、全セルの計算を一度に行う。

NumPy の配列演算は新しい配列を返すので、2 つ目の点に従えば 1 つ目の点も自然に満たされる。

9.2. 1 次元 CA の実装

ECA の 1 ステップの実装は第 4 章「1 次元セル・オートマトン」で示した。時空図全体は、各時刻の配置を 2 次元配列の行に順に格納していけば得られる。

 1def evolve(rule: int, initial: Cells, steps: int) -> Cells:
 2    """初期配置から steps ステップ分を計算し, 時空図を 2 次元配列で返す.
 3
 4    戻り値の形は (steps + 1, セル数) で, 0 行目が初期配置である.
 5    """
 6    table = rule_table(rule)
 7    history = np.zeros((steps + 1, initial.size), dtype=np.uint8)
 8    history[0] = initial
 9    for t in range(steps):
10        history[t + 1] = step(history[t], table)
11    return history

時空図の配列は matplotlib の imshow でそのまま画像として表示できる。interpolation="nearest" を指定しないと、セルの境界がぼやけて表示されることがある。

1import matplotlib.pyplot as plt
2
3from elementary_ca import evolve, single_seed
4
5history = evolve(30, single_seed(201), 100)
6plt.imshow(history, cmap="binary", interpolation="nearest")
7plt.show()

9.3. 2 次元 CA の実装：近傍の数え方

ライフゲームのような外部総和型 CA では、各セルの周囲にある生きたセルの数を数えることが計算の中心になる。代表的な方法が 2 つある。

9.3.1. np.roll による方法

第 5 章「2 次元セル・オートマトン」で示した count_neighbors は、盤面全体を 8 方向に 1 セルずつ巡回的にずらした配列を足し合わせる。np.roll は端からはみ出した要素を反対側の端に回り込ませるので、周期境界条件が自動的に実現される。

9.3.2. 畳み込みによる方法

周囲のセルの数を数える操作は、中心が 0 で周囲が 1 の 3 × 3 のカーネルによる畳み込みである。SciPy の scipy.signal.convolve2d を使うと、次のように書ける（SciPy は本書のサンプルコードには不要なので、試す場合は pip install scipy で別途インストールする）。boundary="wrap" が周期境界条件を表す。

 1import numpy as np
 2from scipy.signal import convolve2d
 3
 4KERNEL = np.array([[1, 1, 1],
 5                   [1, 0, 1],
 6                   [1, 1, 1]], dtype=np.uint8)
 7
 8
 9def step_life(grid: np.ndarray) -> np.ndarray:
10    """ライフゲーム (B3/S23) を 1 世代進める."""
11    n = convolve2d(grid, KERNEL, mode="same", boundary="wrap")
12    return ((n == 3) | ((grid == 1) & (n == 2))).astype(np.uint8)

畳み込みによる方法は、カーネルを取り替えるだけで近傍の形や重みを自由に変えられる。たとえば、第 8 章「発展的な話題」で扱った Lenia のように広い範囲の重み付き平均を使う規則では、高速フーリエ変換（FFT）による畳み込みを使うと効率がよい。

9.3.3. 2 つの方法の比較

本書の執筆環境で、512 × 512 の盤面のライフゲームを 1 世代進める時間を測ったところ、np.roll による方法と畳み込みによる方法はどちらも約 10 ms で、ほぼ同等であった。一方、同じ処理を Python の 4 重の for 文で書くと 1 世代に約 0.7 秒かかり、NumPy を使う方法の約 70 倍遅かった。具体的な時間は環境によって異なるが、セルごとのループを避けることの効果は大きい。

9.4. 境界条件の実装

np.roll や boundary="wrap" が実現するのは周期境界条件である。固定境界条件や反射境界条件を使うには、np.pad で配列の外側に仮想的なセル（ゴースト・セル）を付け足してから近傍を計算し、最後に内側の部分だけを取り出す。

 1import numpy as np
 2
 3
 4def count_neighbors_padded(grid: np.ndarray, mode: str) -> np.ndarray:
 5    """固定境界 (mode="constant") または反射境界 (mode="symmetric") で周囲 8 セルの和を求める."""
 6    padded = np.pad(grid, 1, mode=mode)  # 外側に 1 セルずつ付け足す
 7    rows, cols = grid.shape
 8    total = np.zeros(grid.shape, dtype=np.int32)
 9    for dy in (0, 1, 2):
10        for dx in (0, 1, 2):
11            if dy == 1 and dx == 1:
12                continue
13            total += padded[dy:dy + rows, dx:dx + cols]
14    return total

mode="constant" は外側を 0 で埋めるので、外側を静止状態に固定した固定境界条件になる。mode="symmetric" は端のセル自身を鏡に映した値で埋めるので、図 2.2 の反射境界条件になる。

9.5. 可視化とアニメーション

2 次元 CA の時間変化は、matplotlib.animation.FuncAnimation でアニメーションとして表示できる（サンプルコード game_of_life.py の main 関数を参照）。アニメーションを GIF ファイルとして保存するには、次のように PillowWriter を使う。

1from matplotlib.animation import FuncAnimation, PillowWriter
2
3animation = FuncAnimation(fig, update, frames=200, interval=100)
4animation.save("life.gif", writer=PillowWriter(fps=10))

FuncAnimation が返すオブジェクトは、表示が終わるまで変数に保持しておく必要がある。変数に代入しないと、オブジェクトがガベージコレクションで回収され、アニメーションが止まってしまう。

9.6. 実装上の注意

9.6.1. データ型とオーバーフロー

2 状態の CA では、メモリを節約するために配列のデータ型を np.uint8 にすることが多い。ただし、近傍の和を np.uint8 のまま計算すると、和が 255 を超えたときに桁あふれ（オーバーフロー）が起きて誤った値になる。ライフゲームの周囲 8 セルの和は最大 8 なので問題ないが、近傍が広い規則や状態数が多い規則では、和を計算する配列を np.int32 などにする必要がある。

9.6.2. 乱数の扱い

確率的 CA では、np.random.default_rng(seed) で乱数生成器を作り、シードを指定できるようにしておくとよい。同じシードを使えば同じ結果が再現されるので、デバッグや結果の比較がしやすくなる。本書の図は、すべてシードを固定して生成している。

9.6.3. さらなる高速化

さらに大規模な計算が必要な場合は、次のような方法がある。

表 9.1 高速化の方法

方法

概要

ビット演算

1 セルを 1 ビットで表し、64 セルを 1 つの 64 ビット整数に詰め込んで、ビット演算でまとめて計算する。メモリ使用量も 1/8 になる。

JIT コンパイル

Numba などを使って Python の関数を機械語にコンパイルし、ループのまま高速に実行する。

GPU

CuPy や PyTorch などを使い、配列演算を GPU で並列に実行する。CA は全セルが同じ計算をするので、GPU と相性がよい。

HashLife

盤面を四分木で表し、同じ部分パターンの未来の計算結果を記憶して再利用する [Gosper1984]。規則的な構造が多いパターンでは、何兆世代もの計算を短時間で行える。

ライフゲームなどの CA を手軽に試すには、HashLife を実装したソフトウェア Golly [Golly] を使うのもよい。
